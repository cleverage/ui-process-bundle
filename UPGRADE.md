Upgrade Guide
=============

## Latest

### Deprecated UI options of the launch form

The `entrypoint_type`, `default` and `constraints` UI options are deprecated in favor of the new `form` option (see
[process UI options](docs/reference/02-process_ui_options.md#form-fields)), and will be removed in 4.0:

| Deprecated option   | Replacement                                                                       |
|---------------------|-----------------------------------------------------------------------------------|
| `entrypoint_type`   | `form.input.type`                                                                 |
| `default.input`     | `form.input.default`                                                              |
| `default.context`   | `form.context.<key>.default` (or a free pair with `form.allow_extra_context`)     |
| `constraints`       | `form.constraints`                                                                |

```yaml
# Before
options:
    ui:
        ui_launch_mode: form
        entrypoint_type: file
        default:
            context:
                - key: delimiter
                  value: ','
        constraints:
            - Collection:
                  fields:
                      input:
                          - File: { extensions: [csv] }
                      context:
                          - Collection:
                                fields:
                                    delimiter:
                                        - Choice: { choices: [',', ';'] }

# After
options:
    ui:
        ui_launch_mode: form
        form:
            input:
                type: Symfony\Component\Form\Extension\Core\Type\FileType
                options:
                    constraints:
                        - File:
                              # A CSV file is often detected as "text/plain" (semicolon delimiter, few lines): allow it explicitly
                              extensions:
                                  csv: ['text/csv', 'text/plain', 'application/csv', 'text/x-csv', 'text/x-comma-separated-values']
            context:
                delimiter:
                    type: Symfony\Component\Form\Extension\Core\Type\ChoiceType
                    default: ','
                    options:
                        choices: { 'Comma (,)': ',', 'Semicolon (;)': ';' }
                        required: true
```

- Mixing a deprecated option and its replacement (e.g. `entrypoint_type` and `form.input`, or `constraints` and
  `form.constraints`) raises an `InvalidOptionsException`.
- The HTML names of the free context pairs of the launch form change from `launch[context][<index>][key|value]` to
  `launch[context][extra][<index>][key|value]`: update the functional tests of your application that submit this
  form.
- The `context` child of `LaunchType` is now a compound `FormType` (the declared fields, then the `extra`
  `CollectionType` of the free pairs) instead of a `CollectionType`: update the form theme blocks of your application
  (`_launch_context_entry_*` becomes `_launch_context_extra_entry_*`), the form type extensions and the code using
  `$form->get('context')`.
- The duplicated keys of `default.context` are merged, the last pair wins (two pairs were displayed).
- A process using a deprecated option triggers its deprecations each time its launch form is displayed: expect them
  in the deprecation logs until the process is migrated.

## v3.3

### Route names

The routes of the bundle are prefixed with `cleverage_ui_process_`. The former names are deprecated aliases, removed in
4.0: update the references in your application (`path()` / `url()`, `redirectToRoute()`, security configuration when
`security.configure_firewall` is `false`...).

| Before (deprecated)       | After                                  |
|---------------------------|----------------------------------------|
| `process`                 | `cleverage_ui_process` (dashboard)     |
| `process_<crud>_<action>` | `cleverage_ui_process_<crud>_<action>` |
| `process_login`           | `cleverage_ui_process_login`           |
| `process_logout`          | `cleverage_ui_process_logout`          |
| `process_list`            | `cleverage_ui_process_list`            |
| `process_launch`          | `cleverage_ui_process_launch`          |
| `http_process_execute`    | `cleverage_ui_process_http_execute`    |

The routes of the CRUD pages are generated by EasyAdmin from the dashboard route name, e.g.
`process_process_execution_index` is now `cleverage_ui_process_process_execution_index`.

### Upload directory parameter

The `upload_directory` container parameter is deprecated, use `cleverage_ui_process.upload_directory`: it will be
removed in 4.0. Setting `upload_directory` in your application still works (with a deprecation), unless
`cleverage_ui_process.upload_directory` is also set.

```yaml
# config/services.yaml
parameters:
    # Before (deprecated)
    upload_directory: '%kernel.project_dir%/var/imports'
    # After
    cleverage_ui_process.upload_directory: '%kernel.project_dir%/var/imports'
```

### Twig functions and filter

The Twig functions and filter of the bundle are prefixed with `cleverage_ui_process_`. The former names are deprecated,
removed in 4.0: update your templates (e.g. overridden templates of the bundle).

| Before (deprecated)              | After                                                 |
|----------------------------------|-------------------------------------------------------|
| `log_label()`                    | `cleverage_ui_process_log_label()`                    |
| `log_translation()`              | `cleverage_ui_process_log_translation()`              |
| `log_css_class()`                | `cleverage_ui_process_log_css_class()`                |
| `get_last_execution_date()`      | `cleverage_ui_process_get_last_execution_date()`      |
| `get_process_source()`           | `cleverage_ui_process_get_process_source()`           |
| `get_process_target()`           | `cleverage_ui_process_get_process_target()`           |
| `resolve_ui_options()`           | `cleverage_ui_process_resolve_ui_options()`           |
| `md5` (filter)                   | `cleverage_ui_process_md5` (filter)                   |

### Process bundle 5.4

`cleverage/process-bundle` `^5.4` is required: follow its
[upgrade guide](https://github.com/cleverage/process-bundle/blob/main/UPGRADE.md#v54).

### Doctrine ORM 2

With Doctrine ORM 2, the container compilation fails unless lazy ghost objects are enabled (the legacy proxies cannot
handle the readonly properties of the entities). Nothing changes with ORM 3.

```yaml
# config/packages/doctrine.yaml
doctrine:
    orm:
        enable_lazy_ghost_objects: true
```

### Final classes

`ProcessExecutionManager`, `ProcessExecutionRepository`, `ProcessScheduleRepository`, `ProcessExecuteMessage`,
`ProcessExecutionNotification` and `CleverAgeUiProcessBundle` are marked `@final`, they will be `final` in 4.0
(extending them triggers a deprecation with the Symfony `DebugClassLoader`). The entities stay open. The infrastructure
classes (extension, configuration, commands, controllers, EasyAdmin fields and filters, form types, Messenger and
Monolog handlers, Twig extensions...) are `@internal`.

## v3.1

### Log record context

`LogRecord::contextIsEmpty()` is deprecated (misnamed: it returns `true` when the context is not empty), use
`hasContextInfo()`. The notice is triggered since 3.3.

### Import routes

```yaml
// Before (2.x)

```
